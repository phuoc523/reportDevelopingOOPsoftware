# ScentStation MQTT Protocol v1

Trạng thái: giao thức dùng chung cho Machine Service và Java Device Simulator.
Machine Service hiện triển khai MQTT v3.1.1 publish command, subscribe response,
heartbeat, telemetry, event và alert; xử lý receipt idempotent; lưu telemetry mới
nhất, event history và alert. Java Device Simulator vẫn là công việc tiếp theo.
Broker local dùng TCP; production cần TLS và cấp phát certificate riêng.

## 1. Định danh máy

`machineId` là `machines.id`, được biểu diễn thành chuỗi số thập phân chuẩn
(ví dụ `"9101"`). Giá trị này được dùng trong topic và payload.

Ba định danh trong dữ liệu demo có ý nghĩa khác nhau:

| Giá trị | Trường trong `Machine` | Dùng cho |
|---|---|---|
| `9101` | `id` | `machineId`, topic segment, khóa tham chiếu trong Machine Service |
| `SS-DEMO-9101` | `serialNumber` | Nhãn/serial để hiển thị và bảo trì |
| `device-ss-demo-9101` | `deviceIdentity` | MQTT username để xác thực thiết bị |

Do đó topic mẫu là `scentstation/9101/...`, không phải
`scentstation/SS-DEMO-9101/...`. Backend phải tra `deviceIdentity` đã xác thực
và xác nhận nó ánh xạ tới `machineId` trong topic/payload; không tin
`machineId` do nội dung message tự khai báo.

## 2. Topic và quyền

Topic v1 không có dấu `/` cuối, phân biệt hoa/thường và chỉ dùng machine ID
dạng số như trên.

| Topic | Publisher | Subscriber | QoS | Nội dung |
|---|---|---|---:|---|
| `scentstation/{machineId}/command` | Machine Service | Thiết bị của máy | 1 | Lệnh điều khiển |
| `scentstation/{machineId}/response` | Thiết bị của máy | Machine Service | 1 | ACK/kết quả lệnh |
| `scentstation/{machineId}/heartbeat` | Thiết bị của máy | Machine Service | 1 | Sức khỏe/kết nối định kỳ |
| `scentstation/{machineId}/telemetry` | Thiết bị của máy | Machine Service | 1 | Đọc cảm biến |
| `scentstation/{machineId}/event` | Thiết bị của máy | Machine Service | 1 | Sự kiện không phải alert |
| `scentstation/{machineId}/alert` | Thiết bị của máy | Machine Service | 1 | Tình trạng cần xử lý |

Ví dụ cho máy demo:

```text
scentstation/9101/command
scentstation/9101/response
scentstation/9101/heartbeat
scentstation/9101/telemetry
scentstation/9101/event
scentstation/9101/alert
```

MQTT username của device vẫn là `device_identity`. ACL ánh xạ từng username
đến đúng `machines.id`: device chỉ được subscribe `command` của chính nó và
publish `response`, `heartbeat`, `telemetry`, `event`, `alert` của chính nó.
Tài khoản `machine-service` được publish `command` và subscribe năm topic
inbound trên mọi machine. Người dùng web/mobile không có MQTT credential.
Các ánh xạ demo được cấu hình trong [`infra/mosquitto/acl`](../../infra/mosquitto/acl).

## 3. Envelope JSON chung

Mọi payload là JSON UTF-8, không BOM, có cùng envelope:

| Trường | Kiểu | Quy tắc |
|---|---|---|
| `schemaVersion` | integer | Hiện tại là `1`; thay đổi không tương thích cần version mới |
| `messageId` | UUID string | Định danh một message nghiệp vụ; giữ nguyên khi retry cùng message |
| `machineId` | string | `machines.id` dạng số thập phân chuẩn |
| `type` | string | Phải khớp loại message của topic |
| `timestamp` | string | RFC 3339 UTC, kết thúc bằng `Z`, parse thành Java `Instant` |
| `payload` | object | Nội dung riêng theo loại message |

Không dùng MQTT retained message trên bất kỳ topic v1 nào. QoS 1 là
at-least-once, không phải exactly-once; consumer phải chống trùng bằng
`messageId`, và riêng lệnh phải chống thực thi lặp bằng `commandId`.

Producer tạo một `messageId` mới cho message mới. Khi phát lại cùng message,
giữ nguyên ID đó. Timestamp là lúc producer tạo message, không phải lúc broker
nhận. Các giới hạn tuổi tối đa và sai lệch đồng hồ phải cấu hình ở backend;
không chấp nhận timestamp tương lai vượt ngưỡng. Heartbeat/telemetry cũ không
được làm lùi `lastSeenAt` hoặc ghi đè mẫu mới hơn.

## 4. Message payloads

### 4.1 Backend → Device: `DISPENSE_COMMAND`

Topic: `scentstation/9101/command`.

```json
{
  "schemaVersion": 1,
  "messageId": "c1fd7ad4-29ed-4b67-a482-a174d4ce42e5",
  "machineId": "9101",
  "type": "DISPENSE_COMMAND",
  "timestamp": "2026-11-20T14:00:00Z",
  "payload": {
    "commandId": "cmd-001",
    "action": "DISPENSE",
    "slotId": "91001",
    "durationMs": 420,
    "expiresAt": "2026-11-20T14:01:00Z"
  }
}
```

`commandId` là ID hiện có trong `MachineCommand`, không thay bằng `messageId`.
`slotId` là `machine_slots.id` dạng số thập phân. `durationMs` lấy từ
`MachineSlot.calibratedSprayDurationMs`, không nhận từ client. `expiresAt`
phải tương ứng với `MachineCommand.expiresAt`. Không gửi tenant, payment
reference hoặc dữ liệu khách hàng xuống thiết bị.

Thiết bị từ chối lệnh sai máy, sai slot, hết hạn hoặc đã xử lý. Nếu thiết bị
không thể khẳng định đã/ chưa xịt sau lỗi hoặc mất điện, phản hồi `UNKNOWN`;
backend không tự gửi lại lệnh có thể gây xịt hai lần.

### 4.2 Device → Backend: `COMMAND_RESPONSE`

Topic: `scentstation/9101/response`.

```json
{
  "schemaVersion": 1,
  "messageId": "b92c69f0-56a5-43d2-8725-545d904958ad",
  "machineId": "9101",
  "type": "COMMAND_RESPONSE",
  "timestamp": "2026-11-20T14:00:10Z",
  "payload": {
    "commandId": "cmd-001",
    "status": "DISPENSED",
    "details": "Dispense completed"
  }
}
```

`status` dùng enum hiện có: `ACKNOWLEDGED`, `DISPENSED`, `FAILED`, `EXPIRED`,
`UNKNOWN`. `details` tùy chọn, tối đa 500 ký tự theo `result_details`.
Không gửi riêng `DISPENSE_SUCCESS`/`DISPENSE_FAILED` trên event topic: kết quả
lệnh chỉ có một nguồn sự thật là response. `MachineCommand` hiện không có cột
lưu lượng xịt đo được; v1 không định nghĩa `dispensedAmount`/`dispensedVolumeMl`.

### 4.3 Device → Backend: `HEARTBEAT`

Topic: `scentstation/9101/heartbeat`.

```json
{
  "schemaVersion": 1,
  "messageId": "73dd0fa3-4f2d-4c54-aa60-69fa5c208970",
  "machineId": "9101",
  "type": "HEARTBEAT",
  "timestamp": "2026-11-20T14:00:00Z",
  "payload": {
    "status": "ONLINE",
    "uptimeSeconds": 3600,
    "firmwareVersion": "simulator-1.0.0"
  }
}
```

`uptimeSeconds` là số nguyên không âm. Heartbeat hợp lệ cập nhật lần thấy gần
nhất; chỉ một heartbeat mới hơn và còn trong ngưỡng tuổi cấu hình mới được dùng
để duy trì trạng thái online. Gợi ý ban đầu: gửi mỗi 5 giây, timeout offline
15 giây; cả hai giá trị phải cấu hình được.

### 4.4 Device → Backend: `TELEMETRY`

Topic: `scentstation/9101/telemetry`.

```json
{
  "schemaVersion": 1,
  "messageId": "42df56a0-1730-4ba7-8172-9daf9af4ff3e",
  "machineId": "9101",
  "type": "TELEMETRY",
  "timestamp": "2026-11-20T14:00:05Z",
  "payload": {
    "uptimeSeconds": 3605,
    "doorOpen": false,
    "leakDetected": false,
    "sensorStatus": "NORMAL",
    "slots": [
      {
        "slotId": "91001",
        "remainingPercent": 35.5,
        "sensorStatus": "NORMAL"
      }
    ]
  }
}
```

`remainingPercent` nằm trong khoảng 0–100, tối đa hai chữ số thập phân.
`stockThreshold` của từng slot cũng dùng đơn vị phần trăm. Machine Service lưu
mẫu mới nhất của từng slot trong `machine_telemetry_latest`; mẫu cũ hơn không
được ghi đè mẫu mới. Khi mức đo nhỏ hơn hoặc bằng ngưỡng, Machine Service tạo
alert `LOW_STOCK`; khi mức đo phục hồi trên ngưỡng, alert do device tạo được
resolve. Telemetry không tự trừ tồn kho Operation Service hay đổi `slot_status`.

### 4.5 Device → Backend: `DEVICE_EVENT`

Topic: `scentstation/9101/event`.

```json
{
  "schemaVersion": 1,
  "messageId": "55737a41-8de0-4573-b516-4fc6bc1200ba",
  "machineId": "9101",
  "type": "DEVICE_EVENT",
  "timestamp": "2026-11-20T14:00:08Z",
  "payload": {
    "eventType": "DEVICE_REBOOTED",
    "details": "Device restarted after firmware update"
  }
}
```

`messageId` là khóa chống xử lý lặp cho event. Event không phải alert không tự
đổi trạng thái máy hoặc tồn kho nếu chưa có quy tắc nghiệp vụ tương ứng.
`DEVICE_OFFLINE` được backend suy ra từ heartbeat timeout (thiết bị mất nguồn
không thể publish); `DISPENSE_SUCCESS` và `DISPENSE_FAILED` đi qua
`COMMAND_RESPONSE`, không phát lại trên topic event. `DEVICE_REBOOTED` là event
được device publish; trạng thái online vẫn được suy ra từ heartbeat, không cần
publish thêm `DEVICE_ONLINE`. Các loại event khác phải được chốt trong schema
trước khi handler chấp nhận chúng.

### 4.6 Device → Backend: `DEVICE_ALERT`

Topic: `scentstation/9101/alert`.

```json
{
  "schemaVersion": 1,
  "messageId": "9e435b44-5b63-490c-88a5-68f5b2303d5f",
  "machineId": "9101",
  "type": "DEVICE_ALERT",
  "timestamp": "2026-11-20T14:00:09Z",
  "payload": {
    "alertType": "LEAK_DETECTED",
    "severity": "CRITICAL",
    "slotId": "91001",
    "summary": "Leak detected near slot 91001"
  }
}
```

`severity` dùng enum hiện có `LOW`, `MEDIUM`, `HIGH`, `CRITICAL` để khớp
`MachineAlertSeverity`; `summary` tối đa 500 ký tự. Không có `alertId` hay
trạng thái `ACKNOWLEDGED` do device tạo: ID và vòng đời alert do backend quản lý.
`MachineAlertService` hiện dedupe theo machine/type/slot và gộp lần quan sát
trong alert đang hoạt động.

| Device `alertType` | Mapping hiện có |
|---|---|
| `LOW_STOCK` | `MachineAlertType.LOW_STOCK` |
| `OUT_OF_STOCK` | `MachineAlertType.SLOT_EMPTY` |
| `DOOR_OPEN` | `MachineAlertType.DOOR_OPEN` |
| `LEAK_DETECTED` | `MachineAlertType.LEAK_DETECTED` |
| `SENSOR_ERROR` | `MachineAlertType.SENSOR_FAILURE` |
| `DISPENSE_FAILED` | `MachineAlertType.DISPENSE_FAILED`, gắn với response lỗi cùng `commandId` |
| `DEVICE_OFFLINE` | Backend tạo `MACHINE_OFFLINE` sau heartbeat timeout; không chờ device publish |
| `MAINTENANCE_REQUIRED` | `MachineAlertType.MAINTENANCE_REQUIRED` |

Một lần cố định của sự cố chỉ được gửi qua một đường alert; bản tin lặp giữ
`messageId` nếu là retry. Alert mới cho cùng sự cố có `messageId` mới, còn
dedupe nghiệp vụ sử dụng `MachineAlert` hiện có.

## 5. QoS, retained, session và timestamp

- Dùng MQTT 3.1.1, QoS 1 cho cả sáu topic ở v1.
- Tắt retained message cho toàn broker; không dùng retained cho command,
heartbeat, telemetry, event, response hoặc alert.
- Device dùng clean session; lệnh offline không được xếp hàng để chạy sau khi
reconnect. Lệnh có `expiresAt` và thời hạn lấy từ cấu hình
`MACHINE_COMMAND_LIFETIME_MS`.
- Heartbeat đề xuất mỗi 5 giây, offline timeout đề xuất 15 giây. Backend cấu
hình max message age và future clock skew; từ chối message quá cũ/tương lai.
- Device cần đồng bộ UTC. Backend chỉ cập nhật `lastSeenAt`/telemetry khi
timestamp hợp lệ và mới hơn giá trị đã lưu.
- QoS 1 có thể giao lại. Backend dedupe theo `messageId`; response còn kiểm tra
`commandId`/trạng thái hiện tại. Device phải lưu command đã xử lý đủ bền để
không xịt lại sau reconnect/restart.

## 6. Đối chiếu domain hiện tại và giới hạn v1

| Contract | Domain hiện tại | Ghi chú |
|---|---|---|
| `machineId` | `Machine.id` (`Long`) | Serialize dạng chuỗi số; không dùng `serialNumber` |
| `deviceIdentity` | `Machine.deviceIdentity` | Username MQTT; đối chiếu qua DB với machine ID |
| `slotId` | `MachineSlot.id` (`Long`) | Serialize dạng chuỗi số, xác minh thuộc machine |
| `commandId`, `expiresAt`, status | `MachineCommand` | ID/expiry/status hiện có; kết quả không chắc chắn là `UNKNOWN` |
| `durationMs` | `MachineSlot.calibratedSprayDurationMs` | Backend là nguồn cấu hình |
| MQTT command routing identity | `MachineCommand.deviceIdentity` | Gán từ machine đã resolve trước khi tạo command; chỉ publish tới topic của machine đó |
| alert type/severity/dedupe/status | `MachineAlert`/`MachineAlertService` | Tái sử dụng alert lifecycle hiện có; `MAINTENANCE_REQUIRED` được thêm vào enum |
| telemetry hiện tại | `MachineTelemetryLatest` / `machine_telemetry_latest` | Lưu snapshot mới nhất theo machine và slot; không cập nhật tồn kho hoặc slot status |
| event history | `MachineHistory` / `machine_history` | `DEVICE_REBOOTED` được ghi nhận như history action; không phải raw event archive |
| inbound dedupe | `MachineDeviceMessage` / `machine_device_messages` | UUID message là khóa chính dùng cho transaction idempotency |

Database dùng lại `machines`, `machine_slots`, `machine_commands`,
`machine_alerts` và `machine_history`; không tạo các bảng thay thế. Hai bảng
`machine_device_messages` và `machine_telemetry_latest` bổ sung receipt
idempotency và snapshot telemetry. Kết quả MQTT response cập nhật
`MachineCommand`; trừ tồn kho vẫn thuộc task inventory riêng. `DISPENSE_FAILED`
trên alert không có `commandId` trong payload v1 nên chỉ được ghi thành alert;
response vẫn là nguồn dữ liệu command result.

MQTT 3.1.1 không chuyển tiếp username của publisher trong PUBLISH message.
Mosquitto xác thực username và ACL giới hạn device publish vào đúng topic máy;
Machine Service kiểm tra machine ID trong topic/envelope và registration đang
ACTIVE. Vì vậy cấu hình broker ACL và bí mật device là trust boundary của
identity mapping ở phase này.
